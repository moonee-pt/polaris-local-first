# 云同步不绑死 Vercel

这份文档说明：你的对话数据存在哪里、为什么换部署平台不会丢数据、以及这次"数据全没了"的根因和已经补上的护栏。

## 数据到底存在哪

你的数据正本存在 **MongoDB Atlas**（一个独立的数据库服务），不在 Vercel 上，也不在任何部署平台的服务器里。Vercel 在这里只干一件事：跑两个很小的接口（`/api/sync/push` 上传、`/api/sync/pull` 下载），替你跟 MongoDB 读写。**部署平台 = 一个帮你跑接口的位置，不是数据的家。**

所以"换一个部署平台"根本不用搬数据，只要让新平台跑同一套接口、连同一个 MongoDB 连接串就行。

## 接口代码已经和 Vercel 解耦

核心逻辑抽到了一个不依赖任何平台的模块 `src/engines/server/syncCore.ts`，它只做"收到请求 → 读/写 MongoDB → 返回结果"，不认识 Vercel。上面有两种"外壳"：

1. **Vercel 外壳**：`api/sync/push.ts`、`api/sync/pull.ts`，只是把 Vercel 的请求转交给核心、把核心的结果转回给 Vercel。各约 25 行，纯适配。
2. **自托管 Node 服务器**：`server/selfhost/server.ts`，用 Node 自带的 http 模块跑同一套核心，还顺便托管打包好的前端。任何 VPS / 内网机器 / Docker 都能跑：

   ```bash
   npm run selfhost:prepare                 # 打包前端 + 编译服务器
   MONGODB_URI=<和 Vercel 上那一条一样> npm run selfhost:start
   ```

   然后把前端指向它（构建时设 `VITE_POLARIS_API_ORIGIN=https://你的域名`），或者干脆让这台服务器同源同时提供前端和接口，连 `VITE_POLARIS_API_ORIGIN` 都不用设。

要彻底离开 Vercel，只需要：换一台机器跑上面这个服务器 + 把 MongoDB 连接串 `MONGODB_URI` 填进去。数据库、表结构、同步协议都不用动。

## 这次数据为什么没了（根因）

三个 bug 叠在一起：

1. **本地被清空后，30 秒一次的自动同步没有护栏**。它发现"本地已经没有这些对话了"，就当成"你删掉了它们"，于是往云端发了一串删除指令 —— 云端跟着被清空。触发本地被清空的动作本身可能是清缓存、浏览器回收存储、系统清理等，跟推代码刷新没有必然关系，但一旦发生，旧代码就会把灾难同步到云端。
2. **"从云端恢复"这条路径本身有必现 bug**。恢复时构造的快照没带"附件清单"字段，导入一检查缺字段就直接报错"备份缺少附件清单"，恢复永远失败。所以即便云端还有数据也救不回来。
3. **就算绕过第 2 条，旧恢复逻辑还会顺手清空本地图片附件**（恢复时把本地已有附件当成"本次没有→删除"）。

## 已经补上的护栏

- **空设备护栏**：当本地对话/角色为空、但同步缓存记得云端本来有这些时，判定为"设备被清空"，**不发删除指令**，改由启动时的拉取合并把数据找回来。自动同步和启动同步两条路径都加了。
- **恢复不再报"缺少附件清单"**：云端同步的导入明确跳过"附件域"。
- **恢复不碰本地附件**：因为跳过附件域，云端恢复绝不会清空你本地已有的图片附件（云端本来也不存这些二进制）。

对应的回归测试在 `src/engines/cloudSync.test.ts`，锁住"本地被清空时绝不发删除"这条行为。

## 还剩什么没解决（如实说明）

- **这次丢的对话救不回来**。云端被删除指令清掉后没有副本。唯一能翻出来的是旧 `snapshots` 集合里 2026-10-10 遗留的 2 条测试性对话，真正的聊天内容已无备份。往后有了上面这套护栏，正常不会再复发。
- 图片附件本来就不进云同步（只同步文字数据），这是当初的取舍，没变。
- API 密钥在 `sync_providers` 里是明文存 MongoDB（你之前同意过的代价），解耦不影响这一点。
